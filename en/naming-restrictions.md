# Naming Restrictions

## Symbol Uniqueness

`TypePHP` combines namespaces, class names, and function (or method) names into `C++` function symbols. Each name may be a legal `PHP` name on its own, but the combined name must still remain unique across the entire compiled project and must not produce duplicate definitions with other functions or class methods.

Particular attention is needed: namespace hierarchy and the "class name + method name" boundary use the same separator when generating `C++` symbols. Therefore, the following two `PHP` declarations will conflict:

```php
namespace App {
    class Model
    {
        public function validate(): void
        {
        }
    }
}

namespace App\Model {
    function validate(): void
    {
    }
}
```

Although `App\Model::validate()` is a class method and `App\Model\validate()` is a namespace function, both map to the same C++ symbol:

```text
php_app__model__validate
```

TypePHP does not allow this kind of duplicate definition after combination. When the compiler detects a conflict, it throws a `Fatal error` and lists the two conflicting PHP names and their corresponding C++ symbols. You need to change at least one of the namespace, class name, function name, or method name so that the combined full name no longer conflicts — for example, renaming the namespace function to `validate_data()`.

Consecutive underscores may also conflict with the separator used by the compiler. For example, the following namespace function and class method also cannot coexist:

```php
namespace App;

function user__test(): void
{
}

class User
{
    public function test(): void
    {
    }
}
```

`App\user__test()` and `App\User::test()` both map to `php_app__user__test`. Therefore, you cannot only check whether individual namespaces, class names, or function names are duplicated; the complete compilation symbols generated by combining namespaces, class names, function names, and method names must also not be duplicated.

This restriction applies to the entire static compilation scope, including project source code and third-party libraries included in the compilation; even if two declarations are located in different files, they must not produce the same compilation symbol.
