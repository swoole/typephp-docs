# Compile-Time Attributes

TypePHP provides compile-time annotations using PHP's native Attribute syntax. The compiler reads these Attributes while analyzing source code and converts them into the corresponding compile behavior; unless a specific page states otherwise, they are not written into runtime Attribute metadata.

Attribute arguments support literals, constants, non-empty arrays, nested arrays, and `new` expressions, but must still satisfy PHP's constant expression rules. Plain function calls cannot be used as Attribute arguments; see [Constant Expressions](constant-expressions.md) for the full scope.

## Compile-Time Generation, Zero Dynamic Overhead

The methods generated by `Getter`, `Setter`, `With`, `Printer`, and `Arrayable` are all expanded at **compile time**, and participate in TypePHP's type analysis and AOT compilation as ordinary methods. At runtime the program does not scan Attributes, does not use reflection, and does not dynamically generate or look up methods based on Attributes.

Therefore, the mechanism of these generating Attributes is itself **zero runtime overhead**: calling a generated method is no different from calling an equivalent hand-written method, and is not a dynamic call.

`NotNull`, `NotEmpty`, and `Validate` are also expanded at compile time, with no runtime Attribute parsing overhead; but the parameter checks and exception branches they generate are the explicitly required business checks, and are executed on every call.

`Override`, `MustUse`, and `Immutable` only perform compile-time static validation and generate no runtime code. `ArrayDef` adds no type checks for appends and Map writes whose static types are explicit; `any` keys or values get strict type checks inserted, and explicit index assignment on a List also performs bounds checking. `Native` selects an independent native object model at compile time. `Hot` and `Cold` are converted at compile time into optimization hints for the C++ compiler and perform no runtime Attribute checks. `Constructor` generates an ordinary constructor at compile time, with no additional runtime overhead compared to an equivalent hand-written one.

## Annotation List

| Attribute | Allowed targets | Purpose |
|---|---|---|
| [`#[NoExport]`](no-export.md) | Functions, classes, methods | Exclude a declaration from the public API and exported symbols of a TypePHP library |
| [`#[MethodsFor(...)]`](methods-for.md) | Classes | Declare an extension method provider for a base type, object type, or wildcard target |
| [`#[Getter]`](getter.md) | Instance properties | Automatically generate a public Getter method returning the property value |
| [`#[Setter]`](setter.md) | Instance properties | Automatically generate a public Setter method that modifies the property value |
| [`#[With]`](with.md) | Instance properties | Clone the object, modify the specified property, and return the new object |
| [`#[Printer]`](printer.md) | Classes | Automatically generate `__toString()` from public properties |
| [`#[Arrayable]`](arrayable.md) | Classes | Automatically generate `toArray()` from public properties |
| [`#[NotNull]`](not-null.md) | Function or method parameters | Reject parameter values strictly equal to `null` |
| [`#[NotEmpty]`](not-empty.md) | Function or method parameters | Reject parameter values for which `empty()` is true |
| [`#[Validate(...)]`](validate.md) | Function or method parameters | Validate the parameter using `filter_var()` without modifying its value |
| [`#[Override]`](override.md) | Methods | Force the method to override a parent method or implement an interface method |
| [`#[MustUse]`](must-use.md) | Functions, methods | Forbid discarding the return value of a call |
| [`#[Immutable]`](immutable.md) | Methods, Property Hooks, parameters | Perform compile-time immutability checks on `$this` or parameters in the method |
| [`#[Native]`](native-class.md) | Named classes | Compile the class into a native C++ object not registered with ZendVM |
| [`#[Hot]`](hot.md) | Functions, methods | Hint the compiler to prioritize optimizing high-frequency execution paths |
| [`#[Cold]`](cold.md) | Functions, methods | Hint the compiler to optimize the function as a low-frequency path |
| [`#[Constructor]`](constructor.md) | Instance properties | Generate a public constructor from the properties |
| [`#[ArrayDef(...)]`](array-def.md) | `array` properties | Declare the List element type or the Map key and value types, and check direct element writes |
| [`#[WasmExport]`](wasm-export.md) | Functions | Export a statically-typed function as a WIT interface of a WASI 0.2 Component |

## Namespace Rules

Compile-time Attributes live in the root namespace and fully follow PHP's class name resolution rules. In the global namespace the short name can be used directly:

```php
#[NoExport]
function internalHelper(): void {}
```

In other namespaces, use the fully qualified name:

```php
namespace App\Model;

class User
{
    #[\Getter]
    private string $name = '';
}
```

Short names can also be imported via `use`:

```php
namespace App\Model;

use \Getter;
use \NoExport;

#[NoExport]
class InternalUser
{
    #[Getter]
    private string $name = '';
}
```

`use ... as ...` aliases work as well:

```php
namespace App\Extension;

use \MethodsFor as Provider;
use \Type as TargetType;

#[Provider(TargetType::String)]
final class StringExtensions {}
```

Only names that finally resolve to built-in Attributes in the root namespace have compile-time semantics. For example, the following `Getter` resolves to `App\Model\Getter` and does not generate a method automatically:

```php
namespace App\Model;

class Example
{
    #[Getter]
    private string $name = '';
}
```

Qualified names and `namespace\...` relative names also follow ordinary PHP rules, and are not mistakenly recognized by the compiler just because the trailing name matches.

## Duplicates and Mutual Exclusion

TypePHP's built-in compile-time Attributes are not repeatable by default. On the same declaration, regardless of whether short names, fully qualified names, multiple Attribute groups, or `use ... as ...` aliases are used, resolving to the same root-namespace Attribute is treated as a duplicate and produces a compile error:

```php
use \Getter as ReadProperty;

class User
{
    #[Getter]
    #[ReadProperty] // Compile error: Getter is duplicated
    private string $name = '';
}
```

Mutual exclusion is also checked uniformly at compile time. For example, `Hot` and `Cold` cannot be used on the same function or method at the same time. A specific annotation can be repeated only if it is explicitly declared repeatable; currently none of the built-in compile-time Attributes are declared repeatable.

## Unified Compile Diagnostics

Incorrect usage of compile-time Attributes uses a unified diagnostic format, including:

- the Attribute name;
- the target declaration, such as a class, method, property, or parameter;
- the file and line where the Attribute appears;
- the other source location in the case of duplicates, mutual exclusion, or generated declaration conflicts.

For example, declaring `Validate` twice on the same parameter:

```text
Validate cannot be repeated on the same declaration
[compile-time attribute: #[Validate]; target: parameter $value;
 source: src/User.php:12;
 conflict source: #[Validate] at src/User.php:13]
```

When a method generated by `Getter`, `Setter`, `With`, `Printer`, `Arrayable`, or `Constructor` conflicts with an existing method, the `target` in the diagnostic points to the original Attribute declaration and the `conflict source` points to the existing method, rather than only showing the location of the internally generated method.

## Usage Principles

- The arguments, allowed targets, and concrete behavior of each Attribute are governed by the corresponding second-level page.
- The compiler rejects built-in Attributes used on unsupported declarations.
- User projects may define Attributes with the same name but in other namespaces; they do not trigger TypePHP compile-time features.
- Compile-time annotations can be placed on a declaration together with ordinary PHP Attributes.
