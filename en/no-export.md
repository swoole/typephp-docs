# NoExport Compile-Time Attribute

`NoExport` is used to keep a function, class, or method as a library-internal implementation, without publishing it to other TypePHP projects.

See [Compile-Time Attributes](compile-time-attributes.md) for the namespace rules common to all built-in Attributes.

```php
#[NoExport]
function normalizeInternalData(array $data): array
{
    return $data;
}

#[NoExport]
class InternalCache
{
}
```

Marked declarations still compile normally and can continue to be called within the current library.

## Effect on Export Results

When compiling with `-m lib`, marked declarations:

- are not written into the auto-generated `<target>.stub.php`;
- their corresponding `php_*` functions do not get the library export modifier;
- are not marked as `dllexport` on Windows;
- on platforms such as Linux, with the hidden visibility option, remain internal symbols.

`NoExport` does not delete the implementation, nor does it change execution behavior in ordinary non-library projects.

## Marking Functions

```php
#[NoExport]
function internalHelper(): int
{
    return 42;
}
```

`NoExport` is supported for both PHP-implemented functions and C++ implementation functions declared in the local `.stub.php`.

## Marking Classes

```php
#[NoExport]
class InternalService
{
    public function execute(): void
    {
    }
}
```

Marking a class excludes the entire class and keeps all of its `php_*` methods as library-internal symbols. The class's properties, constants, and methods all stay out of the published stub.

Public APIs should not reference hidden classes. For example, a public function's parameter or return type should not be declared as `InternalService`.

## Marking a Single Method

```php
class PublicService
{
    public function execute(): void
    {
    }

    #[NoExport]
    public function resetInternalState(): void
    {
    }
}
```

In the example above, the class and `execute()` remain public; only `resetInternalState()` stays out of the published stub, and its corresponding `php_*` method is not exported.

## Namespaces

`NoExport` lives in the root namespace. Within a namespace you can use the fully qualified name:

```php
namespace App\Internal;

#[\NoExport]
class Cache {}
```

You can also import the short name or an alias:

```php
namespace App\Internal;

use \NoExport;
use \NoExport as Internal;

#[NoExport]
function helper(): void {}

#[Internal]
class Cache {}
```

Without `use`, `#[NoExport]` inside `namespace App\Internal` resolves to `App\Internal\NoExport` and has no TypePHP compile-time semantics. See [Compile-Time Attributes](compile-time-attributes.md) for the full rules.

## Combining with Other Compile-Time Attributes

`NoExport` can be used together with other Attributes. For example, when an entire class is hidden, methods generated by [`Getter`](getter.md) also remain internal methods:

```php
#[NoExport]
class InternalUser
{
    #[Getter]
    private string $name = '';
}
```
